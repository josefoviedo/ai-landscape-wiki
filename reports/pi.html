01

TL;DR

Pi is a deliberately minimal, terminal-native coding-agent harness from Mario Zechner (creator of the libGDX game framework), now developed at Earendil Inc. — the Vienna public-benefit corporation co-founded by Flask's Armin Ronacher — and shipped under the MIT license. Where Claude Code and Codex are batteries-included, Pi ships four built-in tools (read, write, edit, bash) and a system prompt under ~2,000 tokens, pushing everything else into a TypeScript extension system you assemble yourself. It is provider-agnostic and bring-your-own-key: the same loop runs on Claude, GPT, Gemini, Grok, or local models. Its thesis — that less scaffolding means less hidden context, lower cost, and more predictable behavior — got outside support in August 2026, when a Databricks benchmark found Pi topping pass rates on Claude Opus 4.8 while sending roughly 3× less context and costing over 2× less per task than heavier harnesses. The bill for that minimalism: a steep on-ramp and no safety rails by default — sandboxing and permissions are your responsibility.
02

What it is

New to the idea of an agent "harness"? Start here (skippable)

A large language model on its own only produces text. To make it do things — read your files, run commands, edit code — something has to wrap it in a loop: send the model a prompt, let it request a tool, run that tool, feed the result back, and repeat until the task is done. That wrapper is the harness. Every coding agent has one; usually it's hidden inside a product. Pi's whole argument is that the harness should be small, visible, and yours to change — because everything the harness adds (extra tools, hidden instructions, automatic context trimming) is also something the model has to pay attention to and pay tokens for.

FactPi is the harness, not the model. It ships with exactly four tools — read, write, edit, and bash — and a small core loop. Everything beyond that is a plug-in: TypeScript extensions, lazy-loaded skills, prompt templates, themes, and shareable packages let you rebuild the agent around your own workflow. It runs as a terminal UI with persistent, forkable session trees and several runtime modes, and it speaks to 15+ model providers through one unified API, using your keys.

ReadingJust as telling is what Pi leaves out. It deliberately omits MCP, sub-agents, and background bash from the core. Zechner's argument, echoed by Ronacher, is that heavyweight harnesses "hide context and shift behavior between releases" — so the same prompt silently does different things month to month. Trade press framed Pi as a "harness rebellion" rather than a Claude Code clone.

03

Product & technology

The mental model first: a tiny, transparent loop between one model and four tools — with a plug-in slot for anything you want to add.

You point Pi at a model (via your key) and talk to it in the terminal. Each turn the model may call one of the four tools; Pi runs it, appends the result, and loops. Because the core prompt is small, most of the context window stays available for your code and the task at hand rather than the harness's own machinery. 

you:  "add a --json flag to the export command and cover it with a test"
      -> model reads the relevant files            (read)
      -> proposes an edit to the CLI + a new test  (edit / write)
      -> runs the suite                            (bash)
      -> reads failures, revises, re-runs          (read -> edit -> bash)
      -> stops when green; you saw every step and every token

Minimal context as the core feature

FactPi's system prompt and tool definitions occupy well under 2,000 tokens; one comparison put a heavier harness's system prompt near 22,000. On a small context window that overhead crowds out real work even when cached. Skills load lazily, so the prompt only grows when a capability is actually used.

Extensibility over features

FactRather than ship features, Pi ships a way to add them. TypeScript extensions can add tools, reshape context handling, add permission logic, or wire in sub-agent patterns; skills and prompt templates package reusable behavior; packages let teams share setups. The corollary is that a capable Pi setup is something you build and maintain — the tool hands you the parts, not the assembly.

Provider-agnostic by design

FactOne CLI runs the same agent loop against 15+ providers with your own keys, so switching models is a config change, not a new tool. That independence is why Pi reads as infrastructure: the harness is the constant, the model is swappable.

04

Market position

Pi competes on what it removes. Some category siblings are built on top of it.

Within Model Harnesses and Orchestration, Pi's closest kin are the other model-agnostic runtimes — OpenClaw, Hermes Agent, DeepSeek Harness, Goose, OpenHands, and the research harness SWE-agent — while the orchestration layer (Conductor, Orca, Claude Squad, Paperclip) sits above and drives harnesses like it. Notably, OpenClaw embeds Pi's SDK: Pi is less a rival to the viral consumer harness than the substrate under it. Its sharpest contrast is with the batteries-included flagships in Coding Agents — Claude Code and Codex — which are themselves harnesses but bundle far more scaffolding.

Business

Pi began as Mario Zechner's personal project and is now a product of Earendil Inc., a venture-backed public-benefit corporation based in Vienna, co-founded in 2025 by Armin Ronacher (creator of Flask and Sentry) and Colin Daymond Hanna. On April 8, 2026, Zechner joined Earendil and brought Pi with him; the repository moved from badlogic/pi-mono to earendil-works/pi, the core stayed MIT, and Earendil began building a hosted platform around it.

How the money works

FactThe open-source CLI is free; costs come only from whichever model provider you bring your key for. ReadingEarendil's business is the layer around Pi — a hosted/cloud platform (announced alongside Pi) rather than the CLI itself. That's the familiar open-core shape: give away the client that becomes developers' default, monetize the managed service and team features on top. The thing to watch is exactly that boundary — what stays MIT versus what becomes paid — which is why the public licensing RFC is worth tracking.

Risks & limitations

Where Pi is genuinely demanding, exposed, or unresolved — stated plainly.

  • Steep on-ramp, terminal only. Pi assumes fluency with the command line, git, tmux, and containers, and has no GUI. That deliberately excludes non-technical builders and rapid-prototyping teams who are exactly the audience batteries-included tools court.
  • No safety rails by default — and this is by design. The core has no permission system to restrict filesystem, process, network, or credential access; it runs with the permissions of the user who launched it, with no per-command approval prompts. Sandboxing is your job, not the tool's, which raises the stakes of a bad bash call.
  • Minimalism moves work onto you. A capable setup is assembled from extensions and skills you write and maintain. The four-tool core is honest about this, but it means Pi's real cost includes the engineering time to make it comfortable.
  • Deliberate omissions cut both ways. No MCP, sub-agents, or background bash in core is a feature to purists and a gap to teams who want those out of the box. You can add them via extensions, but that is again work you own.
  • The flattering benchmark is vendor-adjacent. The strongest efficiency claims come from Databricks' own codebase and Earendil's framing of it. The directional point (harness overhead is real) is sturdier than any single pass-rate number, which may not transfer to your stack.
  • Governance and licensing are now company-steered. Pi is an asset of a venture-backed company. The core is MIT today, but roadmap and licensing decisions sit with Earendil and are being worked out in the open (RFC 0015) — an open-core boundary that can move.
Bottom line for an engineering-literate researcher or team: reach for Pi when you want a transparent, low-overhead, model-agnostic loop you fully control — and when you're willing to own sandboxing and setup. If you need guardrails, a GUI, or "it just works" defaults, a batteries-included agent is the safer default. The failure mode to plan for isn't weak output; it's an unsandboxed command running with your full permissions.
